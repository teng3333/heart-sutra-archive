# 試作 v2.1 → v2.2 の変更点（2026-11-14）

段階1で移植した後に、試作（`mandala-prototype.html`）へ入った変更の一覧。移植ずみのコードへ、同じ変更を入れるための資料。
探す時は、下の「試作での目印」を `mandala-prototype.html` の中で検索する。

## 1. 星：四つの層と、複数の動き

- 星を作り直した。四つの層（遠い星は小さく暗く、近い星は大きく明るい）。
- 動きは4種類：横へ流れる／縦へ流れる／奥から手前へ／手前から奥へ。視点が動く作りなので、近い星ほど速く流れる。
- 物語に合わせて切り替える（ゆっくり混ぜる）：無・一点・誕生＝奥から手前へ／生成＝場面が変わるたびに横と縦を入れ替え／秩序へ＝縦／曼荼羅＝奥から手前へ／大波＝奥から手前へ（速く）／一字＝横へ静かに／終わりの無＝手前から奥へ。
- 星の位置の乱数を、縦横に筋の出ないものへ替えた（以前は縦に並んで見えた）。
- 試作での目印：シェーダーの `float h2(`、`vec3 star(`、`uniform vec4 Sk`、`star(ps,0.,spx,ey)`。JS の `SKX`・`SKY`・`SKZ`・`SVX`・`SVY`・`SVZ`・`starN`・`stMode`・`stVel`、`gl.uniform4f(U.Sk,`。
- 試作の操作欄「星の動き」（`id="sm"`）は確認用。本番には入れず、常に「おまかせ」で動かす。

## 2. 横長（16:9）

- PCの全画面では、背景を画面いっぱいの横長で描く。スマホと3D表示は正方形のまま。
- 横長の時は、結末の構図の両脇に、左右対称の曼荼羅を一つずつ足す（枠は合計12のまま）。生成の途中の曼荼羅も横へ広げて並べる。大波と金の広がりは隅まで届かせる。
- **画像保存は正方形のまま。両脇の曼荼羅は画像に写さない**（半分切れて写るため）。
- 描く点の数に上限（約260万）を付けた。大きな画面での重さを防ぐ。
- 表示の大きさが変わったら、描く大きさを必ず合わせ直す（全画面を出た後に大きいまま残る不具合を直した）。
- 試作での目印：`AR`・`KX`・`WN`・`RM`、`function wings()`、`wing:1`、`sp.wing?0:1`、`uniform float As`、`function rs()`、`ResizeObserver`、`function wantWide()`、`function applyWide()`。
- OGS では、曼荼羅の描画先の縦横比から自動で決める（縦横比が 1.15 を超えたら横長として扱う）。試作の「画面の形」ボタン（`id="wd"`）は確認用で、本番には入れない。

## 4. 曲との同期（解析データの計算。段階2で使う）

- 節（フレーズ）の頭の割り出しを改めた。以前は「曲の最初から最後まで4小節ごと」。いまは「基本は4小節ごと。曲調の変わり目に重なるなら、2小節・6小節の節も認めて合わせ直す」。
- 物語の章の変わり目（一点→誕生、誕生→生成、秩序へ→曼荼羅、大波）を、節の頭（なければ小節の頭）へ寄せる。
- 試作での目印：`preAnalyse` の中の `nvw`・`Sc`・`Pv`・`chain`、`fitStory` の中の `function snapP(`。

## 5. 変数名の注意

試作の `frame()` の中には、短い名前の変数が多い（`sm`・`sq`・`sg` など）。新しい変数を足す時は、同じ名前が既に無いかを必ず検索する。v2.2 の作業中、`sm` を上書きして画面が真っ黒になる不具合を一度出した（検査 `verify/sim.js` が検出した）。
