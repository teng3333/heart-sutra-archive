# OGS 曼荼羅背景 要件定義書 v3.2

2026-11-13 · 高尾俊行

v2.0（背景の曼荼羅＋魔法陣の二層）は破棄する。試作を重ねた結果、魔法陣をやめ、**一枚の曼荼羅が一曲ぶんの物語を演じる**形に変わった。同じフォルダの `mandala-prototype.html` が見た目と動きの正解であり、本書はそれを OGS の聞き流しページ（`listen.html`）へ移すための指示である。

着手の手順は `CLAUDE_CODE_START.md` に分けた。まずそちらを読むこと。

## 1. 何を作るか

`listen.html` に、切り替えできる背景を一つ足す。**既存の背景（生きた背景アート `living-bg.js` と波）は残す。** 利用者が「既存の背景／曼荼羅」を選べるようにする。

曼荼羅背景は、一曲を次の物語として描く。

| 章 | 曲の進行（目安） | 画面 |
| --- | --- | --- |
| 無 | 0〜1% | 真っ黒 |
| 一点 | 〜3% | 光の点が一つ生まれる |
| 誕生 | 〜10% | 点が小さな曼荼羅になる |
| 生成 | 〜約77% | 曼荼羅が分裂・合体し、秩序と混沌、収束と発散を行き来する。数は1〜9。流体・煙・植物・炎の質感も現れる |
| 秩序へ | 約8.5% | いまある曼荼羅が、止まらずにそのまま結末の構図へ移っていく。色も同じ歩みで結末の色へ染まる |
| 曼荼羅 | 約3% | 結末の一枚絵。**止まらない**（ゆっくり流れ、回り続ける）。構図と配色は再生のたびに違う |
| 大波 | 3% | 大きな鼓動が一つ。波頭が中心から外へ走り、**通った所から金に染まる** |
| 一字 | 約6% | 金の曼荼羅から粉が立ち、渦を巻いて集まり、にじみ→輪郭の順に、曲ごとの一字が浮かぶ。曼荼羅は沈んで消える |
| 無 | 残り | 字が粉へほどけて闇に還る。闇の中に、曲の字の小さな印・曲名・作者・OGSの名が順に現れる |

独自性は、音に反応する模様ではなく、**曲の構成に沿って一枚の絵が生まれ、完成し、無に還る**ことにある。画像素材は使わず、すべて計算で描く。

## 2. 参考実装の扱い

`mandala-prototype.html` は単体で動く。**ブラウザで開いて最後まで一度見てから着手すること。**（「結末を見る」ボタンで終幕へ飛べる。「曲ファイルを選ぶ」で手元の曲を読ませられる）

- **移植する。作り直さない。** 描画の数式（シェーダ＝GPUで絵を描く小さなプログラム）、結末の構図の作り方、字の作り方、粉の動きは、試作のコードをそのまま使う。見た目を変える「改善」は提案に留める。
- **固定するもの（変えると作り直しになる）**：章の順番、層の構成（4.1）、解析データの形式（5章）。
- **変え続けるもの**：色、速さ、粉の量、字の大きさ、金の強さ、各章の長さなどの数値。試作に直接書かれている数値を**1つの設定ファイルにまとめ**、後から数値だけで調整できるようにする。初期値は試作の値。高尾さんは本番実装の後も試行錯誤を続ける前提である。
- 試作の操作部品（つまみ、ボタン、説明文）は確認用であり、本番には入れない。
- `verify/sim.js` は試作の通し検査（画面なし）。使い方はファイル冒頭に書いた。移植後のコードにも同じ観点の検査を用意すること（6章）。

## 3. 調査済みの事実（2026-11-13 時点。着手時に変わっていないか確かめる）

`listen.html` と バックエンド（`open-gate-sutra` リポジトリの `app.py` ほか）を読んで確認したこと。

- **曲は素の `<audio id="audio">` が鳴らしている。** 音源は R2（別ドメイン）にあり、曲データの `audio_url` で渡る。
- **携帯では、再生中の音をその場で解析してはならない。** `createMediaElementSource` を使うと曲の音が AudioContext を通り、iOS も Android も画面が消えるとそれを止めるので、**曲まで一緒に止まる**（2026-09-25 に実際に起きた。`listen.html` の 600 行付近に経緯がある）。現行は「指で触れる画面か」で分け、携帯では解析していない。
- **既存の背景**は `src/js/living-bg.js`（自動生成。直接編集しない）が `<canvas id="living-bg">` を自分で作り、`window.__livingBG` という窓口で操作される。その上に `<canvas id="waves">`。背景を切り替える仕組みは、まだ無い。
- **画像保存**は `saveShot()`、**動画保存**は `startVideo()`。動画は `MediaRecorder` と `audio.captureStream` を使い、Safari では使えない。曲ごとの `video_policy`（open／owner／none）と、投稿時のキーで制限している。
- **曲データ**（`/api/shelf/…`、`/api/archive`、`/api/track/<id>`）の主な項目：`id` `title` `artist_name` `audio_url` `artwork_url` `axis`（sei／do）`mode`（focus／relax／energy／inspire）`mei` `genre` `tagline` `video_policy` `five_elements`（木火土金水の配合。無い曲もある）。
- **既存の分析データ**（DBの `track_analysis`）は、AI が曲を聴いて付けた**1曲につき1つの値**である（energy、density、tempo_feel、development、pulse_clarity、bpm_estimate ほか）。**「何秒に拍があるか」という時間に沿ったデータは無い。** また energy などの値は、いまの公開 API には出ていない。
- **ローカル確認**：`listen.html` は、`localhost`／`127.0.0.1` で開くと API を `http://127.0.0.1:5001` に向ける。バックエンド側が許可している接続元は `http://localhost:8787` と `http://127.0.0.1:8787`。つまり手元で曲を流すには、バックエンドを 5001 番で、フロントを 8787 番で立てる必要がある。

## 4. 機能要件

### 4.1 層の構成

下から順に重ねる。試作と同じ。

1. 曼荼羅（WebGL の canvas）
2. 粉と字（2D の canvas）
3. クレジット（HTML の文字）

曼荼羅背景を選んでいる間は、既存の `#living-bg` と `#waves` を隠し、`__livingBG` の動きも止める（負荷のため）。既存の背景に戻したら元どおり動かす。既存の背景の見た目と挙動は一切変えない。

既存のほかの層の扱い（2026-11-13 高尾さん決定）：

| 層 | 曼荼羅の間 |
| --- | --- |
| 幻獣 `#beastVeil`（コンテスト1〜3位の曲。中央の球を囲む額） | 隠す |
| 金箔 `#goldLeaf`（最終選考12曲） | 隠す |
| 暗転 `#blackout`（曲の切り替え時の黒い幕） | 既存のまま残す |

- 曼荼羅の画面は、暗転の幕より下に重ねる（幕が曼荼羅を覆えるように）。
- 曲が替わったら、曼荼羅は「無」から始め直す。暗転の幕が下りている間に行う。
- 受賞・最終選考の印を曼荼羅でどう見せるかは、8章の未決事項。

### 4.2 切り替え

- 切り替えの操作部品を1つ足す。**「Save image」の隣に「Mandala」と置く**（2026-11-13 高尾さん決定）。選択は端末に記憶する。
- 初期値は**既存の背景**。曼荼羅は利用者が選んだ時だけ出る。
- 曲の途中で切り替えても、その再生位置の章から正しく始まる。

### 4.3 曲との同期

- **場面の切り替えは、フレーズ（節）の頭でだけ行う。** 節は4小節ごとが基本で、曲調の変わり目に重なる時は2小節・6小節の節も認める（v2.2）。時計まかせでは切り替えない。節の途中で切り替わると流れが途切れる（2026-11-14 高尾さん）。区切りごとに「変化の大きさ」を持ち、大きな区切りでは色・向き・渦の数・秩序と混沌を入れ替え、小さな区切りでは数か向きが一つ動くだけにする。
- 物語の章の変わり目（誕生→生成、生成→秩序へ、秩序へ→曼荼羅）は節の頭に、大波は節の頭か小節の頭に合わせる。
- 流れの速さと激しさは、曲のその時点の勢いに従う。静かな所はゆっくり、激しい所は速く。
- **拍ごとに光って脈打つ演出は、既定で切る**（高尾さんの判断：合っていないと邪魔になる）。
- 解析データが無い曲、読めなかった曲では、試作の「擬似の拍」と同じ動きで代用する。曲は必ず鳴り続ける。
- 早送り・巻き戻しをしたら、その位置の章へ移る。

### 4.4 曲ごとに決まるもの、毎回変わるもの

- **曲ごとに固定**：一字（曲の番号を種にして作る。同じ曲は誰がいつ開いても同じ字）。字の気質は `five_elements` の最も強い要素で決める。無い曲は試作の仮の決め方を使う。
- **再生のたびに変わる**：生成の途中経過、結末の構図（軸が1・2・3・4・5・6・8・9点などの型がある）、配色。配色の激しさの段階は、曲全体の勢いで選ぶ。
- クレジットの曲名は `title`、作者は `artist_name` を使う。

### 4.5 画像と動画

- **画像保存**：既存の「Save image」の中で、曼荼羅背景の時は曼荼羅を写す。**曼荼羅の間は、曼荼羅の画面だけを写す。隠した金箔・幻獣・既存の背景を重ねない**（既存の保存処理は、金箔が有効な曲では見えていなくても金箔を重ねる作りなので、特に確認する。画像にも動画にも同じ）。完成後に押した時は、正面を向いた完成の姿で写す（試作の `poseForImage` と同じ考え方）。字のカードの扱いは 8章の未決事項。
- **動画保存**：既存の動画保存の仕組みに、曼荼羅の画面を渡す。新しい録画の仕組みは作らない。`video_policy` とキーの制限は既存のまま従う。Safari で使えない点も既存のまま。

### 4.6 星・横長・クレジット（試作 v2.2 で追加。詳細は `CHANGES_v2.2.md`）

- **星**：四つの層で奥行きを出す。動きは横・縦・奥から手前・手前から奥の4種類を、物語に合わせて切り替える。
- **横長**：PCで背景が横長に表示される時（全画面など）は、画面いっぱいの横長で描き、結末の両脇に曼荼羅を足す。スマホは正方形のまま。画像保存は正方形のままで、両脇の曼荼羅は写さない。
- **クレジット**：文字の大きさは画面の高さに比例させる。
- **形**（v2.3）：花弁の型は4種類（尖った花弁・丸い花弁・波・角）。生まれたての曼荼羅にも六角・八角などの輪郭を持たせる。
- **色合い**（v2.3）：標準は落ち着いた色。ポップな曲だけ華やかな色にする。**ポップかどうかは、OGS の曲のデータ（速さ・ジャンル・曲評）で決める**（2026-11-14 高尾さん決定）。使う値は段階2で決め、それまでは常に落ち着いた色。
- **左右対称**（v2.3）：曼荼羅の間は、文字のための暗幕を左右対称にする。スマホは常に正方形。

### 4.7 今回は入れないもの

- 3D表示（左右に並べる表示）、ヘッドマウントディスプレイ対応、3D動画の書き出し。試作には入っているが、初回の本番には入れない。後から足せるよう、試作のコードは消さずに設定で切っておく。
- 粉体の曼荼羅。
- WAV での投稿（見送り。2026-11-13 高尾さん決定）。
- 般若心経の漢字の層、ジャケット画像の色の反映。

## 5. 解析データ

### 5.1 方針

携帯ではその場で解析できない（3章）ので、**曲ごとに前もって計算した解析データを置き、再生位置に合わせて読む。** PCでも同じデータを使う（端末で動きが変わらないようにするため）。

### 5.2 形式（試作の `preAnalyse` が返すものを、そのままファイルにする）

1曲につき JSON 1つ。時間はすべて秒。

| 項目 | 中身 |
| --- | --- |
| `version` | 形式の版 |
| `duration` `t0` `t1` | 曲の長さ、本編の始まりと終わり（無音の前後を除く） |
| `bpm` `Tb` `conf` | テンポ、1拍の秒数、拍の確からしさ |
| `beats` | 拍の時刻と強さの並び（拍が不明瞭な曲は無し） |
| `bars` | 小節の頭の時刻の並び |
| `cuts` | フレーズの頭の並び。各要素は `t`（時刻）`w`（変化の大きさ 0〜1）`up`（この先盛り上がるか） |
| `secs` | 曲調の大きな変わり目 |
| `fps` と `it` `e2` `lo` `mi` `hi` | 1秒あたりの刻み数と、勢い・低音・中音・高音の曲線。**そのままだと大きいので、1秒10刻み程度に間引いて整数で持つ** |
| `level` `mean` | 曲全体の激しさの段階（0〜2）と平均 |

1曲あたり数十KBに収めること。収まらない時は間引き方を報告して相談する。

### 5.3 作り方と置き場所（未決。Phase 2 の最初に決める）

候補は二つ。どちらにするかは、実装者が勝手に決めず高尾さんに確認する。

- **A. ブラウザで計算する道具**：管理用のページで曲を読み込み、試作と同じ計算をして JSON を書き出す。試作の計算をそのまま使えるので、試作と結果が一致する。置き場所はフロントのリポジトリ（静的ファイル）か R2。
- **B. サーバーで計算する**：バックエンドの投稿後の処理に足す。投稿のたびに自動で作られる。ただし試作の計算を Python へ書き直すことになり、結果が一致するかの検証が要る。

推奨は **まず A で既存の全曲ぶんを作り、同期が合うことを実曲で確かめてから、B を検討する**。

### 5.4 既存の分析データの使い道

- `five_elements` → 一字の気質。
- `energy` などの値 → 配色の激しさの段階の補助に使える。ただし公開 API に出すにはバックエンドの変更が要る。まずは解析データの `level` だけで進め、必要になったら提案する。
- 時間に沿った同期には使えない（3章）。

## 6. 技術要件・非機能要件

- GitHub Pages の静的サイトのまま動かす。ビルド工程、外部ライブラリ、画像素材を足さない。
- コードは `src/js/mandala/` に分け、`listen.html` への変更は最小限にする。役割で分ける：描画／物語の進行／字と粉／解析データの読み込み／設定値。
- **音楽を止めない**：曼荼羅側で何が起きても再生は続き、既存の背景へ自動で戻る。WebGL が使えない端末でも同じ。**曼荼羅のために `<audio>` を AudioContext へつながない。**
- **性能**：PCで毎秒60コマ、スマホで毎秒30コマ以上。コマ落ちを検知したら、描画の解像度、粉の数、曼荼羅の数の上限の順に下げる。解像度は2倍まで。
- **電池**：タブが裏に回ったら描画を止める。
- **光への配慮**：大波は一度きりのゆっくりした盛り上がりであり、点滅させない。画面全体の明滅は1秒に3回未満（WCAG 2.3.1）。
- **動きを減らす設定の尊重**：端末で「視差効果を減らす」が有効なら、渦と大波の歪みを止め、ゆっくりした変化だけにする（試作に実装済み）。
- **対応環境**：iPhone Safari、Android Chrome、PC の Chrome／Safari／Firefox の最新版。
- **検査**：`verify/sim.js` と同じ観点（章の順番、数値の異常が0、完成時に止まらない、場面転換がフレーズの頭に乗る、色の急変がない）を、移植後のコードに対して機械的に確かめられるようにする。既存の `tests/` の検査も通ること（`node --test tests/*.test.cjs`。変更前は27件通る。`tests/` だけの指定では失敗する）。
