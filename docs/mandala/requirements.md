# OGS 曼荼羅プレイヤー 要件定義書 v2.0

2026-11-11 · 高尾俊行

v1.0（文字と線で組む曼荼羅）は破棄する。試作を重ねた結果、方向が変わった。同梱の参考実装 `mandala-prototype.html` が見た目と動きの正解であり、本書はそれを本番のページに移すための指示である。

## 1. 何を作るか

OGSの試聴ページ（listen.html）に、新しい背景モードを追加する。既存の背景は残し、切り替え可能にする。画面は二層でできている。

| 層 | 中身 | 性格 |
| --- | --- | --- |
| 背景層 | 色鮮やかな複数の曼荼羅が交差し、鼓動し、中心へ吸い込まれ、中心から湧き出す。数も形も絶えず変わる | 予測不能。二度と同じ絵にならない |
| 魔法陣層 | 曲ごとに固有の線画が、曲の進行に合わせて光る線で一本ずつ描かれ、完成し、最後に散る | 曲に固有。同じ曲は必ず同じ形になる |

音に反応する曼荼羅風のビジュアライザーは世の中に多数ある。本作の独自性は次の組み合わせにある。

- 複数の曼荼羅が重なった所で、輪の線が織り合って新しい模様が生まれる
- 数（一と多）と形（円と多角形）が、音をきっかけに予測不能に変わる
- その無常の上に、一曲につき一つだけの印が結ばれる
- 画像を一切使わず、すべて計算で描く。追加容量は数十KB以内

## 2. 参考実装の扱い

`mandala-prototype.html` は単体で動く試作である。ブラウザで開いて必ず動きを確認してから着手すること。

- **移植する。作り直さない。** シェーダ（背景を描くGPU用の小さなプログラム）の数式、魔法陣の生成、発光の描き方は、試作のコードをそのまま使う。見た目を変える「改善」は提案に留め、勝手に入れない。
- **置き換えるのは入力だけ。** 試作は一定テンポの擬似的な拍で動いている。これを実際の音の解析値に置き換える（4.3）。曲の進行も、試作の40秒固定から実際の再生位置に置き換える。
- **数値は設定ファイルに出す。** 試作に直接書かれている数値（変化の間隔、確率、光の強さなど）を1つの設定ファイルにまとめ、後から調整できるようにする。初期値は試作の値とする。
- 試作の操作部品（つまみとボタン）は確認用であり、本番には入れない。

## 4. 機能要件

### 4.1 背景層

すべて試作に実装済み。数値は試作のコード内コメントを参照。

| 要素 | 内容 |
| --- | --- |
| 交差する曼荼羅 | 最大9つ。重なった所は色が混ざり、輪の線が足し合わされて干渉模様になる |
| 鼓動 | 拍ごとに二段で脈打つ（ドクン・ドクッ）。全体の拍動、中心から外へ伝わる波、円周のうねりの3つを重ねる |
| 吸い込みと発散 | 輪の流れる向き、渦のねじれ、曼荼羅どうしの距離、中心の明暗（穴か光源か）が同時に切り替わる |
| 数の変化 | 1つから上限まで不規則に増減。吸い込み・発散とは連動させない |
| 生まれ方と消え方 | 吸い込み中に生まれる時は外から来る。発散中に生まれる時は中心から湧く。発散中に消える時は外へ飛び去る。吸い込み中に消える時はその場で溶ける |
| 形の変化 | 各曼荼羅が独立して、円・三角・四角・五角・六角・八角へ変わる。角数を変える時は一度円に戻る。初期比率は円3割、多角形7割 |

### 4.2 魔法陣層

- **曲番号から形と色を決める。** 種つき乱数（同じ種からは必ず同じ結果が出る乱数）を使い、`Math.random()` は使わない。同じ曲は誰がいつ開いても同じ魔法陣になる。
- **曲の進行に同期する。** 進行度は「再生位置÷曲の長さ」で求める。0〜80%で一本ずつ描かれ、80〜94%で完成して光の波が巡り、94〜100%で外へ広がって消える。
- **早送り・巻き戻しに追従する。** 進行度だけから絵が決まる作りを保ち、どの位置に飛んでも正しい途中経過を表示する。
- **線は光る。** 白い芯の外側に色のにじみを3層、加算合成で重ねる。描いている先端には光る筆先を置く。完成後は鼓動に合わせて強く光る。
- **部品を増やす。** 試作の部品は9種類で、曲ごとの違いがまだ小さい。Phase 3で30種類以上に増やす（弧、波線、入れ子の星形、点列、渦巻き、格子など）。

### 4.3 音との対応

| 音から取るもの | 噛み砕くと | 動かすもの |
| --- | --- | --- |
| 拍 | リズムの打点 | 鼓動を打つ瞬間 |
| 低音の強さ | 太鼓やベースのズンという響き | 鼓動の深さ |
| 中音の強さ | 読経や歌声の帯域 | 輪の流れる速さ |
| 高音の強さ | 鈴やシンバルのきらめき | 金色の輪郭線と魔法陣の光の強さ |
| 音の急な変化 | 曲調が切り替わる瞬間 | 数・形・向きが変わる「きっかけ」 |
| 再生位置 | いま曲の何割か | 魔法陣の進行 |

- **予測不能と曲への同期を両立させる。** 「いつ変わるか」は音の急な変化や拍に合わせる。「何に変わるか」は乱数で決める。見る人には、曲に反応しているのに先が読めない、と映る。音の変化が長く来ない時は、試作と同じ時間間隔で変化させる。
- **拍がはっきりしない曲への対応。** 読経やアンビエントでは拍の検出が外れやすい。検出の確からしさが低い時は拍を使わず、音量のうねりに追従するゆっくりした鼓動に切り替える。
- 音の値はそのまま使わず、なめらかにする（急に上がり、ゆっくり下がる）。
- 一時停止中は鼓動を止め、ゆっくり漂うだけにする。魔法陣はその位置で留まる。

### 4.4 門ごとの性格

初期値。設定ファイルで調整する。

| 門 | 数の上限 | 多角形の割合 | 変化の頻度 | 鼓動 | 色と光 |
| --- | --- | --- | --- | --- | --- |
| 瞑 STILLNESS | 4 | 2割（円が中心） | 試作の半分 | 弱く、ゆっくり | 彩度を落とし暗め。光は控えめ |
| 静 STILL | 6 | 5割 | 試作の7割 | 中 | 試作よりやや落ち着いた色 |
| 動 MOVE | 9 | 8割 | 試作どおり | 強 | 試作どおり鮮やか。光は強め |
| 全 ALL | その曲が属する門に従う | | | | |

### 4.5 操作

- 背景の切り替えボタンを追加する（既存の背景／曼荼羅）。選択はブラウザに記憶させる。
- 曼荼羅表示中、数秒操作がなければ操作ボタンを薄くする。
- 「Save image」は、その瞬間の背景と魔法陣に曲名を入れた正方形画像を保存する。

### 4.6 今回は入れないもの

後から足せるよう、層を追加できる構造にしておく。

- 般若心経の漢字の層（魔法陣の輪に沿って経文を刻む、中心に「空」を置く）
- 投稿されたジャケット画像の色を配色に反映する
- 完成した魔法陣を、曲一覧のアイコンや共有カードに「曲の紋章」として使う

## 5. 技術要件・非機能要件

### 5.1 技術方針

- GitHub Pagesの静的サイトのまま動かす。サーバー処理、ビルド工程、外部ライブラリ、画像素材を追加しない。
- 背景層はWebGL（GPUで描く仕組み）、魔法陣層はその上に重ねた2Dキャンバスで描く。試作と同じ構成。
- 音の解析はWeb Audio APIのAnalyserNode（ブラウザ標準の音解析機能）を使う。
- コードは `mandala/` フォルダに分離し、既存コードへの変更は最小限にする。役割ごとにファイルを分ける：音解析／背景層／魔法陣層／設定値。
- 音解析の開始は、利用者が再生ボタンを押した後に行う（iPhoneでは操作前の音処理が禁止されているため）。

### 5.2 代替方式（音の解析ができない場合）

1. 音源側の設定変更で解析を可能にする（最善）。
2. 曲ごとに音量の変化と拍の位置を事前に計算してJSONファイルで置き、再生位置に合わせて読む。
3. 音を使わず、試作と同じ擬似の拍で動かす。魔法陣は再生位置だけで動くので、この場合も成立する。

### 5.3 非機能要件

- **音楽を止めない**：曼荼羅側でどんなエラーが起きても再生は続き、既存の背景に自動で戻る。WebGLが使えない端末でも同じ。
- **性能**：PCで毎秒60コマ、スマホで毎秒30コマ以上。負荷は曼荼羅の数に比例する。コマ落ちを検知したら、まず数の上限を下げ、次に描画解像度を下げる。
- **電池**：タブが裏に回ったら描画を止める。解像度は2倍までに制限する。
- **光過敏への安全配慮**：画面全体の明滅は1秒に3回未満。拍での明るさの変化幅に上限を設け、全面フラッシュは禁止する（WCAG 2.3.1準拠）。光は強く、明滅は穏やかに。
- **動きを減らす設定の尊重**：端末で「視差効果を減らす」が有効な場合、鼓動と渦を止め、ゆっくりした変化だけにする。
- **対応環境**：iPhone Safari、Android Chrome、PCのChrome／Safari／Firefoxの最新版。
- **読みやすさ**：曲名やボタンが読めるよう、文字の背後に薄い帯を敷く。

## 6. 進め方と受け入れ基準

各フェーズの終わりに、としたんがスマホの実機で見て判断してから次へ進む。

1. **Phase 0 調査**：3章の5項目を報告する。コードは書かない。
2. **Phase 1 移植**：試作を listen.html の背景として組み込む。擬似の拍のまま。背景の切り替えと、エラー時に既存背景へ戻る仕組みまで。試作と見た目が同じであること。
3. **Phase 2 音との接続**：4.3を実装する。魔法陣を実際の再生位置に同期させる。音を消すと鼓動が止まること。
4. **Phase 3 門と魔法陣の拡張**：4.4の門ごとの性格と、魔法陣の部品30種類以上。異なる10曲の魔法陣が一目で見分けられること。
5. **Phase 4 保存と仕上げ**：Save image と、5.3の非機能要件すべて。

最終の受け入れ確認：

- [ ] 既存の背景と機能が以前と同じに動く
- [ ] 曼荼羅を意図的に壊しても音楽が止まらない
- [ ] 同じ曲を別の端末で開いて、同じ魔法陣になる
- [ ] 早送りと巻き戻しで、魔法陣が正しい途中経過になる
- [ ] iPhoneとAndroidの実機で30分連続再生しても、カクつきや異常な発熱がない
- [ ] 全面フラッシュが一度も起きない
